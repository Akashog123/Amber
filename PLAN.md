## 3. Architecture

```
React dashboard (existing)  ──REST + SSE──►  FastAPI backend (new, backend/)
                                               │  SQLite amber.db (meetings, transcript,
                                               │   participants, tasks, records, record_notes, outbox)
Recall.ai bot in Meet  ──webhooks (via ngrok)─►│  /webhooks/recall
   ▲                                           │
   └── output_audio / send_chat_message ◄──────┤  brain.py  → Gemini (answer, extract, tag, MOM)
                                               │  voice.py  → ElevenLabs mp3
                                               │  mailer.py → Gmail SMTP
                                               │  reminder loop (asyncio task, polls tasks due)
replay.py (canned transcript) ─────────────────┘  posts the same webhook payloads locally
```

Key decision: **build a replay harness first.** `backend/replay.py` posts a scripted
transcript (speaker, text, timestamps, joins, chat) to the same `/webhooks/recall` handler.
Stages 1, 3, 4, 5 get built and tested without a bot; if the live join misbehaves in the
morning, a replay run is the fallback demo.

### Files (keep it this small)
```
backend/
  main.py        FastAPI app: REST routes, /webhooks/recall, SSE /api/events, startup reminder loop
  db.py          sqlite3 schema + helpers (stdlib, no ORM)
  seed.py        mock procurement log + equipment list + demo attendees
  brain.py       Gemini calls: answer(), extract_tasks_and_updates(), tag_records(), make_mom()
  recall.py      create_bot(), output_audio(), send_chat(), leave(), get_recording()
  voice.py       ElevenLabs text → mp3 bytes
  mailer.py      smtplib HTML send
  replay.py      scripted meeting → local webhook posts
  test_core.py   wake-word detection, confidence routing, honest-fallback prompt check
  .env.example   RECALL_API_KEY, RECALL_REGION, PUBLIC_URL, GEMINI_API_KEY,
                 ELEVENLABS_API_KEY, ELEVENLABS_VOICE_ID, SMTP_USER, SMTP_PASS
  pyproject.toml fastapi, uvicorn, httpx, google-genai, pypdf, python-dotenv
```

### Data model (SQLite)
```
meetings(id, series_id, title, url, platform, agenda, context_text, status, bot_id,
         started_at, ended_at, mom_json, recording_url)
attendees(meeting_id, name, email)                 -- from dispatch form
participants(meeting_id, name, joined_at, left_at) -- from Recall events
utterances(meeting_id, speaker, text, ts)
chat(meeting_id, sender, text, ts, is_amber)
records(id, kind['procurement'|'equipment'], name, aliases, status, owner, details)
record_notes(record_id, meeting_id, note, confidence, ts)
pending_confirmations(meeting_id, question, candidates_json, created_at, resolved)
tasks(id, meeting_id, series_id, title, owner, owner_email, due_at, status,
      last_update, reminded_at)
```

### API (minimal)
```
POST /api/meetings/dispatch     {title,url,agenda,attendees[],series_id?,file?} → creates bot
GET  /api/meetings              list (dashboard + past meetings)
GET  /api/meetings/{id}         detail: status, transcript, participants, chat, mom, tasks, recording
POST /api/meetings/{id}/stop    bot leaves → triggers post-meeting pipeline
GET  /api/records               mock records + notes (shows tagging working)
GET  /api/events                SSE: status changes, new utterances, Amber replies, record writes
POST /webhooks/recall           transcript.data, participant_events.join/leave/chat_message, bot status
```

### Meeting flow
1. **Dispatch:** extract doc text (pypdf), load linked records + previous series MOM/open
   tasks → `context_text`. Create Recall bot with `recording_config.transcript.provider.recallai_streaming`
   (`prioritize_low_latency`), `realtime_endpoints` webhook for `transcript.data`,
   `participant_events.join`, `participant_events.leave`, `participant_events.chat_message`,
   and `automatic_audio_output` (required for `output_audio` to work — use a short greeting mp3).
2. **Live:** each final transcript segment → store → if it contains "Amber" (also "ember",
   "amba" — ASR misspellings), start buffering that speaker's question → on end-of-question
   → `brain.answer()` → `voice.py` → `POST /bot/{id}/output_audio/`. Every ~60 s (or every N
   utterances) run `extract_tasks_and_updates()` + `tag_records()` on the new window.
3. **End:** bot status "done"/stop → `make_mom()` → save → email attendees → tasks get due
   dates → reminder loop emails owners when due.

## 4. Prompts (the core of grounding)

- **Answer:** "You are Amber, a meeting participant. Reply in 1–2 sentences, under 35
  words, spoken style. For facts about this company, its records, tasks or decisions, use
  ONLY the CONTEXT, RECORDS and TRANSCRIPT below. If the answer is not there, say exactly:
  'I don't have that information in my current records.' General knowledge questions may
  be answered normally." `max_output_tokens≈120`.
- **Extract (JSON):** new tasks `{title, owner, due (ISO or relative), quote}`, updates to
  existing task IDs `{task_id, status, note}`. Pass the existing open tasks list.
- **Tag (JSON):** given records list + transcript window → `[{record_id, note, confidence, alt_candidates}]`.
- **MOM (JSON → HTML):** executive summary, agenda alignment (per agenda item: covered/not),
  decisions, action items with owners + due, open questions, attendance log.

Use Gemini structured output (`response_mime_type="application/json"` + schema) for the
three JSON calls.

## 6. Demo script (≈6 min)

1. Dashboard: show mock procurement log. Create meeting "Weekly Procurement Sync", agenda
   (pump order, chiller maintenance, budget), attach a background PDF, attendees with emails.
   **Send Amber.** Status goes joining → connected.
2. In Meet: people discuss the chiller; Amber stays silent (no interruption).
3. "Amber, what's the status of the pump order?" → spoken grounded answer in a few seconds.
4. "Amber, what was last quarter's marketing spend?" → "I don't have that information in my current records."
5. "Rahul, can you get the vendor quote by Friday?" "Yes, I'll do it by Friday." → task created live.
6. "The pump delivery slipped two weeks" → ambiguous between two pump records → Amber asks in chat → someone confirms → note appears on the record in the dashboard.
7. Chat: type "Amber, who owns the chiller?" → chat reply. (Tier 3)
8. Stop Amber → recap email arrives (summary, decisions, action items, open questions, attendance). Reminder email to the owner shortly after.
9. Dashboard: past meeting view with transcript, tasks, record notes, recording link.

## 7. Risks and fallbacks

| Risk | Fallback |
|---|---|
| Recall key/credits not available tonight | Build everything against `replay.py`; demo stages 1, 3, 4, 5 live from replay and show stage 2 as the only gap. (A self-built Meet browser bot is not realistic overnight.) |
| Bot stuck in waiting room | Host must admit "Amber" — say so in the README and at demo start. |
| ASR mishears "Amber" | Alias list + also trigger when a chat message starts with "Amber". |
| Gemini rate limit (429) | Fall back to `gemini-2.5-flash-lite`; batch extraction every 60 s, never per utterance. |
| Latency too high | Measure each hop; cut context size first, then shorten replies. |
| Gmail blocks SMTP | Confirm App Password in H0; outbox table + "sent" preview in UI as backup. |
| Webhook URL changes when ngrok restarts | Keep ngrok running all night; `PUBLIC_URL` in `.env` read at bot creation. |
